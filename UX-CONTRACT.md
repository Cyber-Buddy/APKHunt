# Apkhunt UX Contract

Visual decisions live in [DESIGN.md](DESIGN.md). This contract owns observable behavior for the upload, report history, report, and dependency workbench.

## Scope and source of truth

This is a local APK analysis product with explicit runtime and network follow-ups. An APK upload is a potentially hostile archive and is validated before decompilation. A scan creates a stored report snapshot and durable history index. Report and dependency pages display that stored snapshot; direct saved-report URLs recover from the report volume if the history index is unavailable, and they do not rerun decompilers, rebuild an SBOM, or re-query OSV as a side effect of viewing.

## Canonical capability ownership

| Capability | Canonical owner | Source of truth | Allowed variants | Verification |
| --- | --- | --- | --- | --- |
| Form | `#uploadForm` and saved-scan POST forms | Server archive limits and app-owned validation | Native file picker with drag-and-drop enhancement | Invalid extension, empty archive, size limit, and archive validation paths |
| Select/Listbox | Native `<select>` controls in the dependency workbench | The saved dependency snapshot | Native select only | Keyboard selection and combined local filtering |
| Scrollbar | `static/css/apkhunt.css` | Shared design tokens | Native overflow in responsive tables | Narrow viewport and keyboard scroll |
| Toast | Flask request flashes and `showToast` | Request outcome or explicit local interaction | Bootstrap-compatible inline status | Screen-reader announcement and dismissal |
| CRUD | History forms plus the delete-confirmation modal | Server-side scan history endpoints | App-owned Bootstrap modal only | Cancel and confirm deletion paths |

* Upload: the `#uploadForm` and its companion script own selection, client-side validation, and truthful indeterminate scan status. The server remains authoritative for archive validation and scan acceptance.
* Home: APK intake is visible in the first screen with a recent-scan list or a useful empty state. The visible Choose APK control contains the native file input as its direct pointer target. The submit action stays disabled until a nonempty `.apk` within the configured upload limit is selected. Invalid selection and drag-and-drop show the same inline error.
* Scan worker: a validated upload returns to history immediately, while one bounded worker performs decompilation, rule checks, static API mapping, TruffleHog detection, dependency analysis, and report save. The shared status dock follows navigation across report and evidence pages and reports completed stage count, elapsed stage time, and actual JADX work units when emitted. It can be minimized and that choice persists locally. The JADX percentage is tool-local and never a whole-scan ETA. An auto-mode error leads to a simplified retry, and if both leave no usable source, bounded isolated DEX retries attempt recovery with imperfect code retained for review. The same imperfect-code mode is optional for APK-level attempts because it measurably slowed a representative scan without resolving its errors. The dock names each DEX attempt without suggesting whole-scan completion. Retry output is labeled partial coverage, and per-DEX output never replaces usable whole-APK source solely because it has more paths. Duplicate active APKs are rejected, and clearing saved data is blocked while a scan is active. Worker status is saved; a service restart marks unfinished work interrupted and asks for a new upload. The deployed server uses one process because this worker state is process-local.
* API evidence: scan-time extraction records absolute URL and Retrofit annotation evidence recursively from recovered and bounded raw APK text, with source path and line. Android XML namespace URLs are ignored; query strings are removed and token-like path segments are redacted. Opening/searching the saved page makes no request to extracted hosts. The user chooses and attests one exact extracted hostname; only that host's concrete, non-root source-code URLs expose route actions. A deliberate route action sends one credential-free HTTPS GET via curl. DNS must resolve exclusively to public addresses and curl pins one resolved address, verifies TLS, ignores proxy configuration, does not follow redirects, and caps time and body size. A 2xx response is labeled `responded without credentials`, never a confirmed authorization flaw without protected-data or action proof and controls.
* Coverage ledger: a saved scan lists bounded APK archive members, raw extraction outcomes, recovered files, actual per-file rule events, skipped work, and decompiler attempts. Missing events and inventory limits remain partial/unknown. Viewing and filtering the ledger never reruns the scan.
* Entry point graph: a saved static graph links manifest components and deep-link declarations to recovered handler-class evidence. Nearby checks and effects are explicitly same-class observations; unresolved call paths, guards, and runtime reachability stay visible. Ranking orders review only and is never a vulnerability verdict.
* Threat model: `/threat-model/<scan_id>` derives a deterministic potential-flow model from the saved entry point graph, API inventory, rule findings, and coverage state without rescanning or contacting a host. Each path joins a manifest component to its recovered handler by identity and draws nearby calls with distinct lexical edge styles. A finding joins a path only by exact manifest component or the same recovered source file, and the relationship is named. External caller, Android dispatch, app code, review questions, counter-hypothesis, source lines, and unknowns stay visible together. STRIDE terms are prompts, never confirmed threat labels. The view supports path search, keyboard-operable path links, focused graph, full screen, and a local JSON export. A bounded diagram omits extra nearby calls with a count, and legacy scans without a graph show an honest empty state.
* Runtime proof: the workbench distinguishes missing ADB, no device, unauthorized, offline, and ready states. For an explicitly exported activity without a manifest permission, the saved graph produces a named launch test. The user selects a ready device and starts it; ADB verifies the installed base APK SHA-256 against the saved report before `am start -W`. The result is bound to the component and hash, but ADB shell launchability does not prove untrusted-app reachability or a sensitive effect. Other graph paths show that no automatic test is defined. Existing manually recorded sessions remain review evidence, not validated findings. Legacy reports without an APK hash require a new scan.
* Legacy API authorization lab: existing saved manual comparisons remain readable at their direct URL. The report and route page direct new work to the integrated API evidence view.
* Secret review: TruffleHog scans recovered material, bounded raw APK members, and extracted binary strings, including decoded `strings.xml` and other text and assets. Provider verification is off unless selected during upload, and the UI names that outbound action. Saved data contains detector, verification state, source, fingerprint, and the full candidate value. The page hides each value until the user reveals it and sends `Cache-Control: no-store`. The local state directory is sensitive. An empty or unverified snapshot is not proof of absence or validity; size and extraction limits are shown.
* History: summary counts appear only when saved scans exist. The shared dock shows queued, running, completed, and failed work; completed work links to its stored report.
* Report: the mobile Sections & filters control opens the existing report navigation, exposes the severity controls, and closes with its close button or Escape. A zero-signal report names the absence of static matches and points to coverage instead of showing an empty severity chart.
* MASVS language: report and PDF counts are static review signals mapped to MASVS groups, never a count of controls passed or independently validated findings. The home page links to a public `/masvs-coverage` page for all 24 controls; its static signal, inventory, and no-control-check states mirror the capability audit in `MASVS_CONTROL_COVERAGE.md`.
* Dependency table: `dependency_dashboard.html` owns a small, local filter for the bounded snapshot. It is not remote search, so no debounce or request cancellation is required.
* Modal: Bootstrap’s modal is the canonical detail overlay. It provides focus handling; the dependency detail script only supplies safe DOM content.
* Status and errors: saved scans show Completed in history, the scan dock, and the report banner. The report links to a separate Coverage ledger, which explains complete, partial, unavailable, and legacy source analysis and exposes technical diagnostics. Every new report records decompiler exit status, elapsed time, and Java/Kotlin versus other scanned-file counts. A non-zero JADX result may contribute recovered source, but source coverage remains labelled partial in the ledger; an Apktool-only result explicitly says that code rules were not evaluated. Flask flashes are reserved for request-level outcomes.
* Network policy: only a manifest-linked Network Security Configuration is structurally evaluated, across recovered base and qualified XML variants. Missing or unparseable linked XML is unknown or partial; the device-selected variant remains unconfirmed. Standalone XML strings do not create cleartext, user-CA, or expired-pin findings, and configuration findings still need runtime destination evidence.
* Deletion: saved scan deletion uses an app-owned Bootstrap confirmation dialog. It names the APK and explains that report and local analysis files are removed.
* Scrollbars: `static/css/apkhunt.css` owns the global scrollbar baseline.

## Workflow ledger

1. Select APK → validate file type and size locally → submit → server validates archive structure and safety bounds → queue a scan or show an actionable error.
2. Scan accepted → return to history immediately → show named active work across navigation with observed stage completion and no fabricated time percentage → link to the stored report when the worker confirms completion.
3. Open report → inspect the saved coverage ledger, entry point evidence, and threat model → select a path-specific action for runtime proof or review API evidence → inspect dependencies and download the exact CycloneDX SBOM.
4. Open dependency workbench → filter locally → inspect a package detail or advisory references → return to the stored report/history without altering the snapshot.
5. Delete saved scan → cancel receives initial focus → confirm server-side deletion → return to history with outcome feedback.

## State model

Upload supports idle, drag-over, selected, validating, submitted, and error. Scan job status and source coverage are separate: a saved job is Completed, while the ledger can record complete, partial, and legacy source coverage. Dependency intelligence supports complete, partial, unavailable, not-queryable, and legacy. A component may be matched, queried-with-no-match, or not-queryable; only the first state may receive a vulnerability severity. Empty inventory and no-filter-results have different instructions.

## Accessibility and responsive behavior

The app targets WCAG 2.2 AA. Actions are native buttons or links; icon-only actions expose labels. Focus is visible. Upload has a real file picker and drag-and-drop enhancement. Filters have labels, and search has an immediate clear button. Tables retain semantics and scroll horizontally on narrow screens. Reduced-motion users do not receive entrance or progress animations.

## Deliberate limitations

The scanner performs static analysis plus optional SBOM/OSV enrichment and opt-in provider credential verification. The threat model is a structured review hypothesis, not a runtime data-flow trace or a confirmed exploit. Activity launch through ADB proves only shell-identity launchability against a matching installed base APK. The integrated route probe establishes only the saved anonymous HTTP response, not whether the route should have been protected. A reportable conclusion still requires a named action, exact APK hash/version, independently observed consumer effect, and causal negative control.
